The agent must locate and consume the exact supplied inputs from the tracker, protected secret store, repository/destination metadata, organization switcher, preserved evidence, service UI, or existing authenticated session.

## Prohibited conclusions and actions

A missing shell variable, failed lookup, empty default organization, missing transcript excerpt, context compaction, `401`, `403`, or agent reasoning must never become:

- “not provided”;
- “not created”;
- “missing” or “nonexistent”;
- “untested”;
- a general `BLOCKED_ON_RESOURCES` status;
- a request that Aaisha recreate, resend, reconfirm, rotate, or replace an input;
- authorization to create or provision a substitute.

Keep resource existence, consumption, and current access separate. Only one exact operation may be `AUTH_BLOCKED`, and only after every approved source has been exhausted. `AUTH_BLOCKED` cannot downgrade `RESOURCE_EXISTENCE=PASS_USER_VERIFIED`.

## Secret-safe consumption

Locating and consuming a user-supplied credential must not expose it in tool output, diffs, logs, process listings, committed files, screenshots, or reports.

- Prefer the approved protected secret store or an existing authenticated session; refer to credentials by protected path/key, never by reproducing their values.
- Do not use a patch/diff operation on a secret-bearing file: even a one-line change can return surrounding secret values. Create or replace secret material only through a non-echoing protected operation, immediately restrict permissions, and never read the values back into the transcript.
- Verify secret installation by file mode, expected key names, non-empty-value booleans, authenticated service identity, and scoped API behavior—not by printing values.
- Never place tokens or passwords in command-line URLs, remote names, shell history, process arguments, Git configuration, committed `.env` files, or evidence manifests. Use environment/file-based credential injection and sanitize all command output.
- Evidence records contain only resource identity, secret-store locator, access result, scope/permission result, and timestamps; credential values remain `[REDACTED]`.
