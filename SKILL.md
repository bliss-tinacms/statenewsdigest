# Astro + TinaCMS Site Changes

> For authority-fragment transformation, multi-category badges, published-only filtering, archive pagination, sitemap fidelity, and stale fullcheck fixtures, read `references/dynamic-demo-rendering-and-publication-contracts.md`.

## Purpose

Leave an existing Astro + TinaCMS site with the requested feature, template or fix in place, while every editable value still comes from the Tina backend and can still be edited in the Tina sidebar. It supports publisher-site migrations without breaking the editor.

## ASTRO-DEMO-LOCK — GLOBAL RULE FOR EVERY ASTRO/TINA SITE

This is a permanent global rule, not a domain-specific preference. **Always load and enforce the canonical global rule in `references/ASTRO-DEMO-LOCK.md` before any Astro demo implementation or migration.** Whenever Aaisha supplies demo/source files, those files are the immutable frontend authority. Clone 100% of their DOM, element types, classes, CSS declarations, font files/imports/axes, exact heading and body font families, font weights/sizes/line heights/letter spacing, text/background/border colours, dimensions, margins, padding, gaps, imagery/assets, scripts/JavaScript, interaction logic, states, breakpoints, sticky/scroll behavior and responsive behavior. The demo typography, palette, geometry and spacing must replace every conflicting old, inherited, boilerplate or destination style; existing global fonts, CSS variables, theme palettes, spacing tokens or components are never permission to keep old styling. Only Tina-backed values and explicitly approved global chrome may differ. **`DEMO-MULTICAT-OVERRIDE-001` — explicit cardinality exception:** when Tina stores a category list, `MULTICAT-LOCK` outranks static demo cardinality. This keyword activates automatically whenever demo item count conflicts with a list-valued Tina category field. A demo with one badge locks that badge's design, not the frontend count; repeat it for every saved category in exact backend order. This required repetition is not a DOM/source-parity violation. Never use `ASTRO-DEMO-LOCK` to justify `categories[0]`, `primaryCategory`, first-item-only rendering, hidden remainder categories or discarded links. Never guess, redesign, approximate, clean up, simplify, substitute or exercise agent judgment over the supplied source. Before implementation, hash and inventory the complete authority. Acceptance requires source↔local and identical source↔live DOM/class/script/computed-style/font/color/spacing/geometry/screenshot/interaction checks plus controlled negatives. Any missing source, unexplained difference, or failed/unrun check is `BLOCKED`, never `done`; builds, SHAs, HTTP `200`, deployment and verbal assurances are not visual proof.

## GLOBAL CORE ASTRO/TINA GATES

**Umbrella trigger: `ASTRO-TINA-MIGRATION-CORE`.** This activates automatically for every new-domain Astro/Tina migration, clone, rebuild, repair, resumption, deployment, or migration-status claim—Aaisha never needs to name it or remind the agent. `USER-PROVIDED-EVERYTHING-001` is a permanent global—not site-specific—input declaration: before migration starts, Aaisha has already personally created, supplied, configured, and tested every required repository, project folder, Tina project/client, organization, branch, token, API/API credential, login, hosting/service resource, account, path, demo, and other migration input. Record `user_provided_everything_user_tested=true` and `agent_assumption_cannot_override_user_verified_resources=true`; her declaration is durable positive evidence even when the current session does not enumerate every item. Agent assumptions have zero authority to override that user-verified evidence. Before any state-changing discovery, implementation, Tina generation, build, commit, push, deployment, live mutation, or status classification, execute `CORE GATE 0` from `references/ASTRO-TINA-MIGRATION-CORE.md`: stop migration processes; load all core rules; check the tracker, preserved user evidence and durable metadata; preserve every resource as `RESOURCE_EXISTENCE=PASS_USER_VERIFIED`; then run the positive evidence preflight and controlled negatives. Resource existence, resource consumption and current access are separate states. Difficulty locating, loading, authenticating to, or consuming a supplied resource—including a missing shell variable, failed lookup, empty default organization, compacted transcript, `401`, or `403`—cannot become “not provided,” “not created,” “missing,” “untested,” a general “blocked on resources” claim, or permission to create a replacement. Only the exact exhausted operation may be `AUTH_BLOCKED`. Only read-only inspection and gate correction are permitted until the gate passes. “Already in process,” inherited work, and compacted context never bypass the gate.

The following nine permanent global core rules apply to every Astro + TinaCMS project. They are not domain-specific and must be loaded whenever their scope applies:

## Instruction

### Prerequisite understanding

1. **Tina is Git-backed.** Content lives in files (`src/content/...`), Tina gives an editor over them, Astro renders them.
2. **Saved backend values win.** Saved Tina/backend values are the source of truth for public output. Local, static or demo text is fallback only and must never silently override a saved value.
3. **The editor contract must survive every change.** Every affected collection keeps rendering from Tina data, SEO fields keep reaching `<head>`, and the Tina admin keeps working: no empty sidebars, stale admin bundles, proxy failures or schema errors.
4. **The island gate comes first.** Before any "done", the live `/tina-island/<collection>?slug=...` payload for each affected form must contain `data-tina-primary`, a real query (`query_len > 100`), meaningful variables and the expected data key. An empty payload blocks completion even if the page looks right.
5. **A supplied mockup is the source of truth.** Copy its structure, classes, CSS, fonts, sizes, weights, spacing, colours, assets and mobile rules exactly. Replace only editable values with Tina fields. Never redesign unless Aaisha asks.
6. **"Done" means the full chain was checked:** sidebar/save, GitHub source, public HTML/meta, island payload. If GitHub/Tina auth, a missing branch or any backend check blocks this, say exactly what is blocked.
7. **A reported broken URL is part of the test set.** Test that exact URL and the whole class of affected routes, not one sample.
8. **Public loaders and editor loaders are different contracts.** Public loaders must fetch Tina Cloud first and may return plain data. Island/editor loaders must also return Tina query metadata (`query`, `variables`, and primary priority). Do not reuse a plain public `getConfig()`/`getPage()` result for an editable island; split it into `getConfig()` and `getEditableConfig()` (and equivalents) when necessary.
9. **Verify the deployed Tina identity as a unit.** The admin bundle, content proxy, public SSR loader and tracker must all use the same client ID, branch and valid token. A split build can make the admin/proxy see new content while public routing silently queries an older project and falls back to local files.
9a. **Rules and preserved positive evidence outrank fresh inference.** Before any migration command or identity/status claim, run the `ASTRO-TINA-MIGRATION-CORE` non-overridable evidence preflight. Check the current tracker, preserved user evidence and durable Tina metadata; verify `bliss-tinacms's Organization`; and preserve already-proven organization/project/client/Site URL identity across context compaction or failed lookups. `401`/`403`, missing transcript output and absent local credentials may block only the specific access operation and must never be reasoned into project nonexistence, wrong organization or loss of prior proof. If reasoning conflicts with a written gate or preserved evidence, stop immediately—the rule/evidence wins, the status must be corrected, and no migration/deployment may resume until the machine-readable preflight and its controlled negatives pass.
10. **Generated Tina files are secret-sensitive, and sanitization is a final-state invariant.** Any production/local Tina command—or a delegated agent running one—may rewrite `tina/__generated__/client.ts` after an earlier cleanup, embedding a token and machine-specific cache path. Never inspect that raw file in logs after a credentialed run. After the last Tina command and after all parallel workers stop writing, restore or sanitize generated files, then use non-printing checks to prove zero active-secret and machine-path hits in Git-tracked text, the final server bundle, and the release archive. Never stage generated changes blindly. See `references/tina-generated-client-safety-and-local-preview.md`.
11. **`PUBLISHER-ADMIN-GATE` — mandatory before `done`.** “Publisher” is the supplied admin account’s username/name, not a restricted role; the account has ADMIN privileges. Never infer limited permissions from that username. In the active session, log into the live admin with the user-provided Publisher/Admin account and personally test every affected collection, document type, Global Config field, media field, sidebar/form, and save path. For each affected path, make a safe temporary change, save it, prove exact public reflection, restore the original value, and prove restoration. Do not rely only on a subagent, API response, island payload, preview screenshot, build, or HTTP check. If login or any live test is incomplete, blocked, or failed, never say `done`; report the exact blocker instead.
12. **Preview visible is not sidebar editable.** Tina can render the iframe while the sidebar still says fields will appear. Allow up to 40–60 seconds, watch the bridge for form discovery/acknowledgement, and wait on a concrete field rather than a fixed short delay.
13. **A successful reindex event is not schema parity.** After dashboard reindex, independently check direct GraphQL fields/types and run a normal cloud-checked Tina build. `--skip-cloud-checks` can keep a deployment running but never justifies calling the Cloud schema synchronized.
14. **Per-document references beat global fallbacks.** For article authors and equivalent references, resolve `postReference || globalDefault`, never the reverse. Derive name, avatar, biography, URL and byline from the same resolved record, then compare the backend selection with every public rendering location.
15. **A custom field must participate in Tina form state.** Updating local React state is not an edit. Call `input.onChange(validValue)`, then prove Save enables, the value survives reload, public output changes, and the exact value is reverted. Collection-derived options must be dynamic rather than hardcoded. Do not assume Tina accepts `type: "reference"` with `list: true`; run the local Tina build. If the active version rejects reference lists, use a `string` list plus an authenticated custom field that paginates the related `...Connection`, derives references from `_sys`, preserves unavailable selected values, and supports refresh after create/delete.
16. **Compatibility overlays are field-specific.** Never spread raw local MDX/frontmatter across a typed GraphQL object: strings can overwrite rich-text/reference objects and make the admin reject an otherwise HTTP-200 response. Preserve upstream typed fields and overlay only the adapted field.
17. **Test the actual save transport.** Tina can use generic `UpdateDocument` directly against its content API rather than a collection mutation through the site proxy. Observe operation and destination without logging credential-bearing bodies, and make emergency reversion independent of whether the expected response listener fired.
18. **Exactly one primed form may be primary.** Island endpoint payloads can already contain `data-tina-primary`; if client priming preserves that marker, global header/footer forms can become primary alongside the article and the sidebar may open Global Config. Inspect every live `data-tina-form`, require one primary document, and verify the actual browser-loaded bridge body rather than only the built file.
19. **Content-editor login is not schema-administration authority.** Before concluding that an authenticated account can repair schema drift, observe the actual Tina Cloud reset/reindex network response. The dashboard may optimistically show `Indexing` even when `POST .../db/<client>/reset/<branch>` returns `403 not authorized to reset repository cache`. Distinguish live `/admin/` editing access from project owner/admin permission, and ask for elevated project access only after proving the permission boundary.
20. **Cloud-schema checks must bypass a same-origin content proxy.** A production `contentApiUrlOverride` may correctly route browser/editor queries through the site, but it makes `tinacms build` construct `/db/<client>/status/<branch>` against that site and parse an HTML page as JSON. For direct Cloud validation/sync, temporarily unset only the content-API override variables while retaining client ID, branch and token; then run the normal cloud-checked build. Restore the production override for the deployed build.
21. **Treat field renames as additive Cloud migrations.** Tina Cloud can report a successful reset/reindex yet retain an older schema when a change removes or renames a field. Keep the legacy field with the same type (hide or clearly label it), add the replacement field, regenerate `tina/tina-lock.json` and generated schema files with `tinacms dev`, commit/push them, then force a schema refresh and prove both direct GraphQL introspection and a normal cloud-checked build pass. Remove the legacy field only in a separately verified migration.
22. **Direct Tina mutations are document writes, not safe partial patches.** A mutation such as `updateConfig(params: { seo: ... })` can serialize a document containing only the supplied top-level fields and delete omitted configuration such as redirects, forms, code injection, and footer settings. Before emergency mutation-based reversion, capture the complete document and send the complete mutation input; afterward compare every top-level field with the baseline, not only the field under test. Media uploads must also be deleted through the configured media-store DELETE endpoint after the original document is restored.
23. **A Tina content proxy must stay transparent.** It may forward request bodies, auth/API-key headers, upstream status/body, and safe CORS headers. It must not strip unsupported GraphQL fields, rewrite rich text or references, synthesize mutation results, merge local frontmatter into typed Cloud objects, or persist compatibility overrides. These hacks conceal schema drift and can turn a normal full-document save into destructive partial data. Fix schema parity instead.
24. **Passenger runtime paths and server-side island transport are separate concerns.** Load runtime `.env` relative to the startup module/application root, not the process working directory. A generated client that correctly uses a same-origin content proxy in the browser can fail when called by Passenger SSR; editable server loaders should fetch Tina Cloud directly with the exact generated query and variables. Do not pass an unresolved generated-client promise directly into `requestWithMetadata()`: the helper may intentionally catch the rejection and return an HTTP-200 form with `query: ""`, `variables: {}`, and no authoritative document, so an outer `try/catch` never runs. Fetch Tina Cloud directly first; otherwise await the generated request yourself, require the expected data key plus non-empty query and variables, then call `requestWithMetadata()` once. Empty form metadata must fail closed rather than masquerade as a working island. For author/profile archives, apply the same island wrapper to every canonical/editor alias and give the invariant one stable regression ID across migration policy, executable fullcheck, and Publisher/Admin acceptance. When parsing `data-tina-primary`, detect boolean-attribute key presence rather than requiring a non-`None` value. See `references/author-island-identity-and-gate-id.md`.
25. **Temporary live tests are atomic transactions.** Capture the original, edit, save, prove public reflection, restore immediately, save again, and prove restoration before starting another field. Keep a cleanup journal. In automation, keep the document's `dirty`/`marker_saved` flag true until all three restoration proofs pass: the original reloads from authenticated Tina, cache-busted public output contains the original at the mapped selector, and the marker is absent. Clicking Save or receiving a mutation response is not the point at which cleanup responsibility ends. A public poll timeout may be delayed indexing rather than a failed restore; run an idempotent emergency restore, then independently inspect authenticated admin and cache-busted public output before classifying the result. If time or tool limits approach, restoration outranks more testing. A reflected value whose restoration is incomplete remains `BLOCKED`. For rich-text media, do not rely on Ctrl+Z surviving Save, reauthentication, or a browser-context reset: capture the complete Git-backed document and body-image baseline first, use an explicit image-node removal path, verify the parent document rather than a nested Image sub-form, then prove public absence and exact document equality before continuing.
26. **Exact-source rebrands need three proofs: source parity, containment and dynamic-data parity.** When the user says copy the demo/classes/CSS 100%, preserve the demo class tree and declarations one-for-one, changing only dynamic bindings and asset URLs. A stylesheet loaded last is not isolated: legacy rules can still supply properties the demo never declares (`min-height`, `display`, `max-width`, padding, borders, text transforms). Put a dedicated class on the homepage Tina-island wrapper, apply a scoped reset **before** the untouched copied source block, and keep any later compatibility guard separate. A scoped `all: revert` outranks a later universal `*` reset by specificity, so immediately re-express the demo's universal baseline (`box-sizing`, margin, padding, and any other universal declarations) under the same scope; otherwise buttons can become content-box tall and footer lists regain browser indentation. Do not attach the homepage scope to a generic page island that also renders articles/pages; add a homepage-specific island registry entry when necessary. For a dynamic demo section such as Latest Stories, preserve its exact card classes while mapping the backend's sorted latest records into those slots, then compare the live API's top records with the rendered titles/URLs. Prove key computed invariants (header bottom equals hero top, quote inner width equals viewport/section width, text-card border is none while image border matches source) and compare desktop plus every source breakpoint against the standalone demo.
27. **Schema, content, and handwritten queries are one migration.** Whenever a homepage/global model changes, update its Tina schema, content document, generated lock/types, and every custom GraphQL fragment in `src/lib/data.ts` or island loaders. A stale handwritten query can fail and silently trigger old Cloud/local fallback data, producing a visually stale page even though the new MDX is correct.
28. **Global footer ownership is structural as well as visual.** When a homepage section is clarified to be part of the global footer, move its markup into the reusable `<footer>` so it appears exactly once on every intended route; a matching background or adjacent placement is not enough. Preserve its existing Tina data source unless a complete Global Config schema migration is approved and Cloud-verifiable. If its fields remain in a page document, give the extracted footer section a dedicated island using that page's editable loader so article and generic-page routes still receive real edit metadata. Avoid `Footer -> islands -> Footer` import cycles, then verify `footer.contains(section)`, `!main.contains(section)`, count `1`, and the island payload on both home and non-home routes. After relocation, inspect computed styles: ancestor rules such as `.ft a` can outrank the CTA class and silently reduce button-label contrast even at opacity `1`; correct only the CTA with a more specific selector and preserve its geometry.
29. **A production canonical can become localhost even when `.env` is correct.** `astro.config.mjs` can execute before `.env` values appear on `process.env`, causing a localhost fallback to be baked into `Astro.site`, canonical/OG/Twitter tags, RSS and sitemap output. Load the environment explicitly during config evaluation and add a shared-head request-origin guard for SSR. Verify exact live metadata on home, page and article routes plus RSS/sitemap; do not trust an SEO extension cache over the actual DOM.
30. **Public Astro email addresses must remain normal HTML, not Cloudflare-protected placeholders.** If a live page shows `[email protected]`, first prevent edge transformation with the documented `Cache-Control: no-transform` response directive and `<!--email_off-->...<!--/email_off-->` fence around public-site output. Preserve full Tina values and ordinary `mailto:` anchors. Apply the same source policy to the reusable Astro/Tina boilerplate so the defect does not recur on future sites, but do not silently alter unrelated live sites. Use split data attributes plus client-side `mailto:` activation only when response-level control is unavailable or verified insufficient. Prove cache-busted raw CDN HTML contains the expected plain addresses and `mailto:` URLs, no exact `data-cfemail=` attribute or `/cdn-cgi/l/email-protection`, and that the hydrated DOM still has readable exact text, exact `mailto:` URLs, contrast and viewport-contained geometry on every affected route. See `references/cloudflare-email-obfuscation-and-tina-contact-fields.md`.
31. **Brand typography is a computed-style and font-binary contract, not a font-import guess.** Before styling a page to “match the site,” inspect representative live brand headings, body copy, labels and links with `getComputedStyle`; do not infer the brand family from fonts loaded in `<head>`, a previous mockup, a UUID filename, or a CSS variable name. Read the reference `@font-face` ranges and inspect WOFF/WOFF2 internal metadata: never relabel an unrelated font binary as the expected family. For variable fonts, preserve and verify both weight and width axes; the right family at `100%` stretch still fails a condensed demo that specifies `72%` or `75%`. A font declared only on the page wrapper is not isolated: any direct global or component-scoped `h1`/`h2`/`a`/`p` rule can beat inheritance and silently supply a different family, colour, weight, decoration or spacing. Give the page scope explicit descendant declarations for every owned typography role, include semantic `h1`–`h6`, preserve intentional exceptions such as monospaced eyebrow labels with more-specific rules, and use scoped `!important` only when an identified legacy declaration otherwise wins. Verify `document.fonts` ranges/status plus the exact computed family, weight, stretch, size, line-height, colour and overflow on live cache-busted desktop and phone routes across every template class. If the user says the font is still wrong, treat that as evidence that the prior visual pass was insufficient: re-audit the binary, axes, cascade and computed styles rather than defending the intended CSS. See `references/astro-tina-sitemap-dynamic-branding-guard.md`.
32. **Person identity assets must stay synchronized across every rendering surface.** A portrait swap on an editorial roster is not complete when only the dedicated team document changes. Search Tina content, homepage blocks, author cards, quotes and shared components for every affected name/image reference. Before editing, record a `person -> current image path` baseline; for a two-person swap, derive both destination assignments from that immutable baseline rather than applying sequential replacements that can accidentally assign the same portrait twice. Repeated historical swaps make filenames unreliable evidence of identity, so distinguish “the file currently assigned to this person” from “the person named in the filename,” and use the user's latest explicit pairing plus visual/hash evidence when available. Unless the user clearly requests a one-way copy, wording established in the task as “swap X to Y” should preserve a two-way exchange; state the resulting before/after matrix internally before patching. Apply the final `person -> image path` table to every surface the user expects to match, especially homepage roster cards after a team-page change. Prefer changing references rather than exchanging file bytes under misleading filenames. Verify the live DOM tuple `(visible name or alt, src, naturalWidth > 0)` on each affected route, then visually inspect the actual card section so a technically loaded but mismatched/cropped portrait cannot pass.
33. **Template-to-template matching is a measured geometry contract.** When the user asks one component to match “the other template,” identify the actual source component from its content/DOM, then compare source and target at the same desktop, tablet and phone widths. Record outer width, grid columns, panel width, padding, heading x-position, ancestor `max-width`, and computed heading family/size/weight/line-height/letter-spacing. “Container width” may mean a split ratio plus fixed inset rather than a centered `max-width`. Copy the source CSS declarations and breakpoint sequence exactly for the requested component instead of estimating from the screenshot or introducing an unrelated `clamp()`. Keep unrelated body breakpoints unchanged, re-measure equality locally, and repeat on a cache-busted live URL after activation. See `references/template-component-computed-style-parity.md`.
34. **A screenshot-directed micro-edit is a one-property contract.** When the latest message points to one artifact—such as “remove the top line”—treat that latest instruction as the active scope, identify the exact owning selector/property, and make the smallest possible diff. Do not combine it with earlier unresolved visual feedback or opportunistically change related spacing: removing a border does not authorize collapsing its padding. Prove the live result with both the relevant computed property and a tight screenshot crop. See `references/screenshot-directed-css-micro-edits.md`.
35. **`TINA-FULLCHECK` must be executable and field-class complete.** Never call an island check, build, preview, HTTP 200, or unrelated body-field mutation a full check when the affected feature is SEO. Query Tina directly and compare it with cache-busted raw SSR HTML and browser DOM for title, description, canonical, robots, Open Graph, Twitter and relevant JSON-LD. A route must consume one Tina-first public loader; do not import the same MDX document separately and let a bundled snapshot compete with live data. Put local fallback inside the loader, add a build-time source-authority invariant, and negative-test that invariant with the old local-first pattern. If a prior release omitted the SEO comparison, state that the gate was not actually run rather than defending the partial check. See `references/tina-seo-authority-and-executable-fullcheck.md`.
36. **Full gates are collection-complete, not representative.** When the user requests `TINA-FULLCHECK`, `PUBLISHER-ADMIN-GATE`, or “all collections,” derive the configured collection set from the exported Tina collection objects and require exact equality with the gate's explicit test map. The gate fixtures must be real destination documents and routes discovered from the current repository/backend; after a clone or rebrand, inherited boilerplate filenames make the script test nonexistent content and must be replaced before execution. One Page document, Home plus Our Team, or a public HTTP sweep is not full coverage. For every configured collection, run an authenticated live-admin marker save, authenticated Tina read, cache-busted unauthenticated public reflection where applicable, exact admin restoration, authenticated backend restoration, and public restoration. Reacquire nested/list field locators after save and check whether a field is already visible before clicking a section label, because the label may have become a disabled breadcrumb. Tina Cloud sign-in may open in a popup: wait for the popup before clicking Enter Edit Mode, authenticate there, then return to the original admin page after the popup closes. Restoration outranks further coverage. The omission negative test must fail fast with a controlled coverage-mismatch result before GraphQL construction or missing-key dereferences. After the gate’s restoration saves create Git commits, fetch/fast-forward the final restoration tip, rebuild, redeploy, and rerun read-only proof without repeating the mutation loop. Report each collection as its own row. See `references/tina-collection-complete-fullcheck-and-publisher-gate.md`.
37. **A valid Tina response can belong to the wrong publication, and a current token cannot repair a failed index.** For cloned/rebranded sites, verify dashboard repository and branch, then require returned Global Config identity to match the local destination before any Cloud record can override repository content. Distinguish wrong project, stale read token and failed branch index with separate evidence. After schema changes, briefly run `tinacms dev`, parse `tina/tina-lock.json` to prove the new fields exist, sanitize generated clients, and scan only staged text files for secrets and machine paths. A local/skip-cloud build and repository fallback are containment, not release certification. When media configuration changes, require **both** layers: (a) an authenticated live-admin Media Manager open/list request that returns `200` and visibly renders controls/assets, and (b) a reversible authenticated upload/delete with post-delete absence. A direct Cloudinary SDK upload can pass while Tina's list route fails—for example when `CLOUDINARY_ROOT_FOLDER` is missing—so it never certifies the Media Manager by itself. See `references/tina-rebrand-cloud-identity-token-lock-and-media-proof.md` and `references/tina-self-hosted-media-manager-cloudinary.md`.
37a. **A live migration defect must harden the canonical migration gate, not only the affected site.** When a failure reveals a missing invariant that can recur across Astro/Tina migrations, repair the live site and, in the same task, update the repository's `TINA-MIGRATION-GOLD.md`, its executable validator/negative test, and the matching reusable skill reference. Do not wait for Aaisha to repeat this instruction. ## Workflow

**Installation is a prerequisite, never a stopping point.** After a dependency, browser, runtime, or helper installs successfully, continue automatically into the build, implementation, and verification steps in the same run. Do not pause for “continue,” and do not present installation success as the deliverable when working code or a verified deployment was requested.

After each numbered sub-step, state what was done, where the evidence is, and `PASS`, `BLOCKED` or `FAIL`. Do not start a sub-step that depends on one that has not passed. Do not merge sub-steps into one claim.
